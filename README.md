# 天象选号 · 双色球

按当天干支、节气、建除、五行生成双色球号码的**娱乐工具**。
网页版，自带一个零依赖小服务，开奖后自动同步官方数据；号码与设置全存本地。

---

## 为什么是网页，不是小程序

原计划是做成微信小程序，查证后确认**个人主体做不了**。微信开放社区的官方说明原文：

> 当小程序涉及彩票服务，属**个人主体小程序未开放类目**，建议申请企业主体小程序。
> 请下架尚未开放服务类目内容或申请企业主体小程序合规提审，
> 否则代码审核环节将面临**因类目不符被驳回**情形。

社区里有人问「只提供纯机选工具、不做查询和预测行不行」，同样被驳回。
也就是说，**哪怕去掉一切"预测"表述，只要是双色球选号，个人主体都过不了**。

另外还有两条隐性障碍，即使换成企业主体也绕不开：

1. **玄学内容**：平台运营规范禁止宣扬封建迷信，"宜忌定号"容易被判定违规
2. **地图接口**：内嵌地图要申请地理位置接口，个人主体基本不批；
   而请求外部开奖数据必须配置已备案的合法域名，此项目没有自有域名

所以改成**单文件网页**：功能一个不少，且没有审核、没有备案、没有服务器。
在手机上用浏览器打开，再「添加到主屏幕」，体验与小程序差别很小。

## 怎么用

**电脑**：双击 `start.bat`，浏览器会自动打开 `http://127.0.0.1:5173`。

**手机**：
1. 把整个文件夹传到手机（微信文件传输助手 / 网盘都行）
2. 用浏览器打开 `index.html`
3. 浏览器菜单 →「添加到主屏幕」，之后像 App 一样点开

> **三种跑法，同一份 `index.html`**

| 打开方式 | 号码/天象 | 开奖数据 | 内嵌地图 |
|---|---|---|---|
| `start.bat`（本机服务） | ✓ | ✓ 实时，8 分钟刷新 | ✓ |
| GitHub Pages（线上） | ✓ | △ 只读仓库里存好的那份，不会自己更新 | ✓ |
| 直接双击 `index.html` | ✓ | ✗ 浏览器禁止 file:// 联网 | ✗ 需要安全上下文 |

直接双击时页面会明确提示"离线打开"，此时**手动填写开奖号**照样能比对，
其余功能一个不少。想两者都要，就走 `start.bat`，或部署到 GitHub Pages。

`start.bat` 做的事只有一件：用 Node 起一个本地服务（默认 `127.0.0.1:5173`），
既托管页面，也把福彩官网的数据转给页面。**只监听本机，不对外，不需要备案。**

## 部署到自己的 GitHub Pages

**本项目的线上地址**：https://cj584361.github.io/ssq-tianxiang/

### 先讲一个坑：线上版没法自己更新数据

福彩官网（`www.cwl.gov.cn`）**只对国内 IP 开放**。实测：

| 从哪儿访问 | 结果 |
|---|---|
| 本机（国内宽带） | ✅ 正常返回 |
| 海外代理（allorigins / codetabs） | ❌ Cloudflare 522，连不上 |
| 中彩网 `jc.zhcw.com`（换一个源） | ❌ 校验 Referer 必须是 `zhcw.com`，浏览器直连被拦 |
| 免费第三方彩票 API | ❌ 实测 10 余个，全部失效或要付费 key |

所以 GitHub Actions（跑在海外机房）**抓不到**，`data.json` 不会自己变新。
仓库里的 workflow 保留着，成本为零，万一哪天通了就自动生效，但**不能指望它**。

### 让线上保持最新：`sync-push.bat`

双击仓库根目录的 `sync-push.bat`：

```
本机（国内网络）──抓官网──▶ data.json / history.json ──git push──▶ 仓库
                                                                  └─▶ Pages（1 分钟内生效）
```

- 数据没变化就什么都不做，不会刷一堆空提交
- 抓取失败退出码 2，不动现有文件
- 想全自动：把 `sync-push.bat` 加进「任务计划程序」，每天 **21:40** 和 **22:10** 各跑一次
  （周二/四/日开奖，21:15 开、21:30 前后官网才出数）。电脑开着就永远是最新的。

页面自己会算「本来该有哪一期」：对不上就把右上角标成 **「缺 10/29 那期」**（橙色）
或 **「落后 N 期」**（红色），不会拿旧数据冒充最新。

### 首次启用步骤（只需做一次）

1. 仓库 **Settings → Pages → Source** 选 `Deploy from a branch`，分支 `main`、目录 `/ (root)`，保存
2. **Settings → Actions → General → Workflow permissions** 确认是 `Read and write permissions`
   （workflow 若要提交 `data.json`，只读会推送失败）
3. 等一两分钟，访问 https://cj584361.github.io/ssq-tianxiang/

### 几点补充

- **GitHub 定时任务会被限流**：workflow 里写的 `*/15` 不作数，实测间隔 3–7 小时。
  即使网络通了，也别指望准点。
- **中彩网是个好源，但只给自家页面用**：`jc.zhcw.com` 的接口字段齐全（含一至六等奖注数与单注奖金）、
  带 `Access-Control-Allow-Origin: *`，看着完美——但它校验 Referer，
  浏览器和海外服务器都过不去，本项目没有采用。
- **想要"电脑不开机也自动更新"**：只有一条路——把抓取放到**国内**的服务器上
  （腾讯云函数 SCF / 阿里云 FC 的免费额度就行），函数里带 `Referer` 抓官网，
  存到云数据库或再推 GitHub。海外 serverless（Vercel / Cloudflare Workers）同样不通。

## 五个模块

**1. 今日天象**
- 公历日期、星期、距下一个节气天数
- 年 / 月 / 日三柱干支（年柱以**立春**为界，不是元旦）
- 十二建星（建除满平定执破危成收开闭），附释义与黄道/黑道判定
- 日主五行、冲煞方位、月相（含被照亮百分比）

**2. 今日号码**
- 每天只给**一组**：6 红 + 1 蓝，不铺垫、不列一堆备选
- **一期一组**：号码绑的是这一期，不是打开页面那一天。同一期的两三天里
  不管哪天打开，都是同一组号；换期才换号
- 显示「取号依据」，写明这一组是按哪一天的天象取的
- 可用日期左右箭头切到任意一天，也可以**直接在卡片上左右滑动**；
  翻到过去是「回看」模式，用那天本身的天象
- 「换一组」在同一期里换编号，刷新后仍保留你选的那组
- 一行小字给出**距本期停售还有多久**（20:00 停售，21:15 开奖），30 秒走一格。
  盯停售而不是开奖——开奖你不需要做任何事，停售才决定还能不能买
- 「复制号码」一键复制，带日期与干支，粘给朋友也知道出处

**确认 → 自动判奖**

点「确认这组」后，页面会先算出这组号等的是哪一期（最近的未来开奖日），然后：

| 情况 | 表现 |
|---|---|
| 还没开奖 | 徽标「未开奖」，写明几月几日周几 21:15 开奖，并承诺开奖后自动比对 |
| 已过开奖时间但没拿到数据 | 提示「应该已经开奖了」，引导点「立即同步」 |
| 开奖了，中了 | 徽标「中奖」，直接给出奖级与固定奖金 |
| 开奖了，没中 | 徽标「未中奖」，附红球命中数、蓝球是否命中 |

判断依据是开奖公告的**开奖日期**与这组号的目标期匹配，不是靠期号推算，
所以跨年、跨批次都不会错判。结果一旦判出就冻结保存，之后官方数据继续刷新也不会覆盖掉。
确认时会同时在「我的号码」留一条记录，开奖后自动回填期号与结果。

**我的号码**

存下确认过的每一组，右上角直接标结果，不用自己一个个对：

| 徽标 | 含义 |
|---|---|
| 待开奖 | 等的那期还没开 |
| 一等奖 … 六等奖 | 已判出，金色高亮 |
| 未中奖 | 对了，没中 |
| 已开奖 | 比当前能拿到的最新一期更早，没有历史数据可回查，不瞎判 |

**3. 上期开奖**
- 自动同步中国福彩官网的最新一期，号码以**大号红蓝球**展示（6 红 + 1 蓝）
- 带期号、开奖日期与星期、奖池金额、当期销量
- 开奖后自动刷新：平日 8 分钟一次，周二/四/日 21:15–22:15 加密到 2 分钟一次
- 暂无数据时球位显示虚线空球；取不到数据时退回折叠的手动填写区
- 附**奖级对照表**（六档中奖条件与奖金），判出奖级时能立刻对上为什么

**4. 奖金走势**
- 近 30 / 60 / 100 期两条曲线：**奖池**（左轴·亿元）与**一等奖单注奖金**（右轴·万元）
- 双 Y 轴：两者量级差两个数量级（10 亿 vs 800 万），同轴会画成一条直线
- 点某个点，弹窗给出该期奖池、销量、一等奖注数×金额、二等奖注数×金额
- **一等奖空开**（0 注 0 元）时折线在该期**断开**，不画成「奖金归零」；
  区间内有几期空开会写在图下
- 图不平滑：样条插值会画出数据里没有的峰谷，奖金数字不能这么「好看」
- 图表用 ECharts，但**懒加载**——卡片滚进视口才去下那 1 MB 脚本，不拖首屏
- ECharts 拿不到时（断网 / CDN 被墙 / `file://` 离线）自动退回手写 SVG 双折线，
  图照样能看，只是没有 tooltip

**5. 周边彩票店**
- 填高德 Key → 内嵌地图 + 3 公里内店铺列表
- 不填 → 一键跳转高德搜索

## 选号算法

```
种子 = 日期 | 年干支 | 月干支 | 日干支 | 建除 | 五行 | 节气
随机数 = mulberry32(FNV-1a(种子 + "#" + 序号))
红球 = 1–33 洗牌取前 6 个并升序
蓝球 = 1–16 独立抽取
```

**这个设计是确定性的**：同一天、同一序号，必然得到同一组号码。
这样做不是为了"更准"，而是为了让号码**有出处**——你昨天看到的和今天看到的一致，
而不是每次刷新都变，那会显得像随便糊弄。

**它不能提高中奖概率。** 双色球每期是独立随机事件，任何算法都做不到。

## 历法实现说明

没有用农历数据表，全部走天文公式现算，所以能覆盖任意年份且不依赖外部数据。

| 项目 | 方法 | 精度 |
|---|---|---|
| 日干支 | 儒略日 `(JDN + 49) % 60` | 精确 |
| 年干支 | 以立春（黄经 315°）为界 | 精确 |
| 月干支 | 五虎遁 + 节气月 | 精确 |
| 节气 | 太阳视黄经，迭代求 15° 整倍数 | 误差约 15 分钟 |
| 建除十二神 | `(日支 − 月建 + 12) % 12` | 精确 |
| 月相 | 日月黄经差（简化 ELP） | 误差数小时 |

**已与三个黄历站点交叉对账**（2026-10-24 至 10-28 连续五天）：

| 日期 | 本程序 | 站点 |
|---|---|---|
| 10-24 | 辛未日 · 收日 | 辛未日 · 收日 ✓ |
| 10-25 | 壬申日 · 开日 | 壬申日 · 开日 ✓ |
| 10-26 | 癸酉日 · 闭日 | 癸酉日 · 闭日 ✓ |
| 10-27 | 甲戌日 · 建日 | 甲戌日 · 建日 ✓ |
| 10-28 | 乙亥日 · 除日 · 霜降 · 冲蛇煞西 | 同左 ✓ |

**没做二十八宿**：查证时发现不同黄历站给同一天的星宿不一致
（2026-10-28 有的说"壁水貐"、有的说"井木犴"），数据源本身有分歧，
做上去反而会给出错误信息，所以略去。

## 开奖数据同步

**数据源**：中国福彩官网开奖公告接口
`https://www.cwl.gov.cn/cwl_admin/front/cwlkj/search/kjxx/findDrawNotice?name=ssq`

官方数据，与公告页一致，不是抓第三方聚合站。

**为什么需要 `server.js`**

这个接口不返回 `Access-Control-Allow-Origin` 头，浏览器里直接 `fetch` 会被跨域策略拦掉；
`file://` 打开时更彻底，连请求都发不出去。所以由本地服务同源转发：

```
浏览器 ──GET /api/latest──▶ server.js ──▶ 福彩官网
        ◀── 精简 JSON ────
```

**刷新策略**

| 场景 | 行为 |
|---|---|
| 打开页面 | 先渲染本地缓存，同时拉一次最新 |
| 平时 | 每 8 分钟一次 |
| 开奖日 21:15–22:15 | 每 2 分钟一次（双色球周二、四、日 21:15 开奖） |
| 切回标签页 | 距上次同步超过 8 分钟就补一次 |
| 后台标签页 | 暂停轮询，不浪费流量 |

**缓存**：服务端缓存 8 分钟，一期结果不会变，避免反复打官网。
官网临时故障时返回上次结果，右上角标「官网取不到」，不会白屏、也不假装是新数据。

**右上角那个标签说的是「缺不缺数据」，不是「文件多旧」**：
拿开奖日历算出「本来该有哪一期」，跟手上这期的日期比——

| 标签 | 含义 |
|---|---|
| 已同步（绿） | 就是最新一期 |
| 缺 10/29 那期（橙） | 落后 1 期，点「立即同步」或跑 `sync-push.bat` |
| 落后 N 期（红） | 落后 2 期以上 |
| 官网取不到（橙） | 这次没连上数据源，显示的是上次存的 |

**页面按顺序试三个数据源**，前一个不通才走下一个：

1. `/api/latest` —— `server.js` 或云端 Node 版，实时
2. `data.json` —— GitHub Pages 上仓库里存的快照，**不会自己变新**（见上文「先讲一个坑」）
3. `http://127.0.0.1:5173/api/latest` —— 直接双击 `index.html` 时的兜底

https 页面不会去碰 http 本地地址，避免浏览器按混合内容拦掉；反之 `file://` 打开时
也不会去试同源接口（不可能存在）。

**奖金走势的历史数据**走同样一套：

1. `/api/history` —— `server.js`，缓存 6 小时，回源失败退本地 `history.json`
2. `history.json` —— 仓库里存的快照，由 `sync-push.bat` 更新
3. `http://127.0.0.1:5173/api/history` —— `file://` 打开时的兜底

`history.json` 约 14 KB / 100 期，只存画图用得上的字段（期号、日期、奖池、销量、
一二等奖注数与金额），不含号码。

**失败降级**：全部不通就提示具体原因，并自动展开手动填写入口；天象、选号、判奖逻辑全在本地，离线可用。

**隐私**：只请求开奖公告，不上传任何本地数据。期号与号码存在 `localStorage`。

## 地图配置

1. 到 [高德开放平台](https://lbs.amap.com/) 注册，创建应用
2. 添加 Key，服务平台**必须**选 **Web 端（JS API）**，选成「Web 服务」用不了
3. 在同一个页面把 **安全密钥（securityJsCode）** 一起复制出来 —— 它与 Key 成对出现，在该 Key 右侧「设置」里
4. 两个都粘到页面「周边彩票店 → 配置密钥」，点保存

> **安全密钥不是可选项。** 高德自 2021-12-02 起，之后申请的 Key 必须搭配安全密钥使用，
> 否则地图加载不出来或取不到数据（错误码 10008 / `INVALID_USER_SCODE`）。
> 本页会在加载 JS API 之前写入 `window._AMapSecurityConfig`，顺序错了设置就无效。

> **插件也要声明。** `AMap.Geolocation`（定位）和 `AMap.PlaceSearch`（周边搜索）都是插件，
> 不在脚本 URL 里 `&plugin=` 声明就是 `undefined`，`new` 的时候直接抛异常。
> 本页两条路都走了：URL 参数 + `AMap.plugin()` 兜底。

若 Key 设了域名白名单，要把访问地址加进去（本地是 `http://127.0.0.1:5173`，
线上是 `https://cj584361.github.io`）。两者都存在浏览器 localStorage，不上传任何地方。

**定位权限**：浏览器只允许 https、localhost、127.0.0.1 上定位。`file://` 直接打开时
定位必然失败，页面会说明原因并按默认位置（天安门）继续搜索，地图本身能拖动。

## 地图排错

页面会把失败原因直接写在图框里，不再给一句通用提示。按显示的内容对号：

| 你看到的 | 原因 | 怎么改 |
|---|---|---|
| 脚本已返回，但没有生成 AMap 对象 | Key 被拒绝，或被广告拦截插件拦了 | 核对 Key 是否完整、类型是否为「Web 端（JS API）」 |
| Key 授权没通过 · 提到安全密钥 | 缺 `securityJsCode` 或填错 | 到控制台复制该 Key 的安全密钥，一起保存 |
| Key 授权没通过 · 提到域名白名单 | Key 设了白名单，当前地址不在里面 | 把图框里显示的「当前地址」加进白名单 |
| 地图初始化失败 · 带 `INVALID_USER_KEY` | Key 无效或类型错 | 同上，确认类型是 JS API |
| 地图出来了，但查不到店铺 | 地图能出图，服务接口被卡 | 多半仍是安全密钥或配额问题 |
| 附近 3 公里内没搜到彩票店 | 搜到了，确实没有 | 换个位置或直接用下方按钮跳高德 |

图框里还会回显掩码后的 Key（如 `abcd…3456（32 位）`），可以先确认是不是粘错了、
位数对不对，再往下查。完整报错可以去浏览器控制台看 `INVALID_USER_` 开头的代码。

```
├── sync-push.bat                  抓官网 → 推 GitHub，让线上跟着更新
├── package.json                   声明 node 启动方式
├── scripts/sync-draw.js           抓官网 → 写 data.json（本地与 Actions 都能跑）
├── scripts/sync-history.js        抓近 100 期 → 写 history.json
├── .github/workflows/sync-draw.yml 定时跑上面两个脚本（海外抓不到，仅留作兜底）
└── README.md
```

接口：

| 路径 | 说明 |
|---|---|
| `GET /` | 页面 |
| `GET /api/latest` | 最新一期开奖（精简 JSON，含期号/红球/蓝球/日期/销量/奖池） |
| `GET /api/history` | 近 100 期奖金数据（缓存 6 小时，回源失败退本地文件） |
| `GET /api/health` | 服务状态与缓存时间 |
